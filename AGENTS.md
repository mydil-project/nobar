# AGENTS.md

## Project

Static NOBAR (watch-together) web app. No package.json, bundler, or tests. Plain HTML/CSS/JS with ES modules and Firebase CDN imports.

## Run

- Open via HTTP server, not `file://` — ES modules and CDN imports fail on file protocol.
  - Example: `npx serve` or `python -m http.server` from this folder.
- Syntax check JS: `node --check js/<file>.js`

## Architecture facts

- Playback sync is driven by Firebase RTDB path `state` (`currentUrl`, `playing`, `videoPosition`, `playbackStartTimestamp`, `activePlaylistId`). Only the host writes `state`; viewers only read and seek/play to match.
- Sync mode arsitektur: **waktu host = kebenaran tunggal**. Host menjalankan `startHostReanchor()` (interval 500ms, dari `initAll`): bila drift `|currentTime − formula| > 0.5s` dan `playing` + non-YouTube → host menulis ulang `videoPosition` + `playbackStartTimestamp` ke posisi aktual. Viewer hanya mengejar formula (`expectedPosition`) → otomatis mengikuti host dan tidak mendahui. Playback normal drift ≈ 0 → hampir tidak ada tulisan (hemat Firebase, tidak ada loop). Guards: skip bila `!sessionActive` (setelah logout), `Number.isNaN(duration)`, atau host `paused` (tulis pertama setelah 4s pause, lalu throttle max 1 tulisan / 4s) — cegah spam tulis saat autoplay host gagal/buffer.
- Progress bar host: klik seek **langsung** set `hostVideoPlayer.currentTime` (wajib — re-anchor 0.5s akan membalik posisi bila hanya tulis state). Saat `state.playing === false`, patch hanya `videoPosition` (seek tanpa resume); saat playing, refresh `playing` + `playbackStartTimestamp`.
- Logout / signed-out (`onAuthStateChanged` null): set `sessionActive = false`, pause + `stopVideoElements()` + `hideYoutubeFrame()`, reset `lastLoadedUrl = ''` (host) / `initialSeekDone = false` (viewer) → re-anchor & `checkSchedule` berhenti, video tidak tetap bunyi di background → `location.replace('login.html')`. `onAuthStateChanged` host `await registerHost()` sebelum `initAll()` (pastikan `users/{uid}.role = 'host'` ada sebelum tulis `state` — dibutuhkan security rules).
- Clock skew handled via `.info/serverTimeOffset` → `serverOffset`. Use `Date.now() + serverOffset` for schedule/state math.
- HLS streams (`.m3u8`) use global `hls.js` from CDN (`Hls`); YouTube URLs load in an iframe (`hostYoutubeFrame` / `userYoutubeFrame`). Detection: `isYoutubeUrl` / `parseYoutubeId`.
- Default stream when playlist empty: constant `DEFAULT_STREAM_URL` in `js/host.js` (Red Bull TV m3u8). Host `playDefault()` resets `state` to it when playlist is empty or active item removed.
- Presence: `users/{uid}` dengan `online`, `role` (`host` | `viewer`), `name`, `photo`, `onDisconnect` (**tanpa `email`** — `users` read semua user terautentikasi, jadi jangan simpan email di sana; cabang viewer menulis `email: null` agar key lama terhapus). Chat: `chat` via `onChildAdded`.
- Playlist schedule: host-only `checkSchedule()` (1s interval, guarded by `scheduleBusy`). Viewers must not write playlist/schedule/state. `scheduledTime` is ISO string; sort is by scheduled time on every `onValue(playlist)`. `checkSchedule()` memakai item **past-due paling akhir** (`t > matchedTime`), sama dengan viewer `tickAsync()`.
- Badge jadwal di list playlist **tidak** di-render ulang tiap detik (bikin scroll & listener putus): `renderPlaylist()` hanya jalan saat event `playlist`, label dihitung oleh `scheduleBadgeFor(item, now)`; tick 1 detik `updateNextFilmInfo()` sekalian memanggil `refreshPlaylistUi()` yang menulis `textContent`/`className` badge + class `.active` per item secara granular (ref disimpan di `playlistItemRefs` / `playlistBadgeRefs`).
- Playlist items host-only writes: `push` add, `remove` delete, `update` for status/reschedule/play. Item shape: `{ title, url, status: 'pending'|'active'|'completed', scheduledTime?: ISO }`. **Status lifecycle**: `pending` (default) → `active` (via `checkSchedule` when due, or manual ▶ on scheduled item) → `completed` (via `ended` handler, `playDefault`, or `playPlaylistItem` when switching). `playDefault()` and `playPlaylistItem()` finalize the previous `activePlaylistId` item to `completed` before changing state. `saveReschedule()` resets `completed`/`active` → `pending` when rescheduling to a future time (except currently-playing item). `updateNextFilmInfo()` filter excludes `completed` and `currentState.activePlaylistId` but NOT blanket `active` (an item stuck `active` with a future schedule will still show as "Selanjutnya").
- Manual default: tombol `#btnPlayDefault` di bar `movie-info` host → `playDefault(true)` (force, ganti `state` ke `DEFAULT_STREAM_URL` walau `currentUrl` masih terisi). Viewer tidak punya tombol ini.
- Sync/async mode: path `settings/syncMode` (`'sync'` | `'async'`, default `'sync'`). Only the host writes it (toggle `#btnSyncMode` in `host.html`); viewers read and show badge `#viewerModeBadge`. **Sync** = viewer follows `state` (current behavior). **Async** = viewer ignores `state`, computes playback from playlist `scheduledTime` vs server clock (`now - scheduledTime`); before first schedule / gap after item ends → `DEFAULT_STREAM_URL` (constant duplicated in `js/index.js`). Items without `scheduledTime` never play in async mode. `tickAsync()` skip item `status === 'completed'` kecuali sedang aktif (`asyncActiveId`) — viewer yang tertinggal tetap boleh menyelesaikan item-nya. **Item yang jadwalnya sudah lewat akan langsung memotong item yang sedang main** (host lewat `checkSchedule()`, viewer lewat `tickAsync()` yang memilih item *past-due paling akhir*) — ini perilaku yang disengaja, bukan bug; `asyncGapId` hanya menutup jeda `ended` lokal → host menandai `completed`.
- RTDB security rules: `database.rules.json` (deploy via Firebase CLI / Console). `state`, `settings`, `playlist/*`, dan identitas host di `chat` write hanya `auth.uid === HOST_UID`; `chat` viewer write auth + `uid` cocok `auth.uid`; `users/{uid}` write hanya own uid + **validate: `role === 'host'` hanya boleh bila `auth.uid === HOST_UID`**; root `.read/.write` false. Role host hanya ditulis `js/login.js` / `js/host.js` `registerHost()` untuk `HOST_UID` — user biasa tidak bisa set `role: 'host'` lagi.

### Playlist item actions (host only)

- **Play**: `.btn-play` or dblclick → `playPlaylistItem(idx)`. Finalizes previous active item (if different) to `completed`, then sets `status: 'active'` if item has schedule, then writes `state`.
- **Reschedule**: `.btn-sched` → modal `#rescheduleModal` (`#rescheduleInput` datetime-local). Save: `update` `scheduledTime` (ISO); resets `completed`/`active` → `pending` (except currently-playing item). Empty input + save clears `scheduledTime` and sets `status: 'pending'`. Does **not** stop active playback. Close: Batal / overlay click / Esc.
- **Delete**: `.btn-del` → `removePlaylistItem(id)`.

### Auth + fullscreen (PC)

- Login: **hanya** `login.html` — `signInWithPopup` first; on `auth/popup-blocked` fall back to `signInWithRedirect`. Setelah auth: `HOST_UID` → `host.html`, selain itu → `index.html`. `host.html`/`index.html` tidak punya layar login; signed-out → `location.replace('login.html')`.
- Fullscreen (desktop only, `pointer: fine`): jangan panggil saat/sesaat setelah `signInWithPopup` — activation habis / popup diblokir. `tryAutoFullscreen()` dipanggil dari event `canplay` video pertama (atau saat iframe YouTube dimuat). Jika tetap ditolak (butuh gesture), toast `showFullscreenHint()` tetap fallback (klik → `requestDocumentFullscreen()`).
- **Fullscreen hanya boleh lewat `.video-frame`** (`hostPlayer` / `userPlayer`), tidak pernah `video.requestFullscreen()` atau andalkan gesture bawaan. Dua jebakan yang sudah ditutup: (1) `dblclick` pada `<video>` di-`preventDefault()` di `initPlayer()` — kalau tidak, Chrome (desktop & Android) mem-fullscreen-elemen `<video>` dan `.fs-title` ikut hilang; (2) klik ⛶ set `fsRequested = true` supaya `tryAutoFullscreen()` tidak bisa "mencuri" fullscreen yang masih pending (guard `document.fullscreenElement` di `requestDocumentFullscreen()` masih `null` selama request ⛶ pending → `.video-frame` berakhir tidak jadi elemen fullscreen, judul muncul sesaat lalu hilang). `toggleFullscreen` hanya `exitFullscreen()` kalau `document.fullscreenElement === player`; kalau yang fullscreen `documentElement` (jalur auto) → `player.requestFullscreen()` (browser auto-switch). Fullscreen browser (`F11`) bukan DOM fullscreen → `.fs-title` memang tidak muncul di sana.
- Autoplay (**opsi A**): semua `play()` lewat `tryPlay()` — **selalu bersuara**, **tidak pernah** fallback `muted` + **tidak ada** toast suara sama sekali (`#soundToast` / `showSoundToast` / `hideSoundToast` sudah dihapus). Jika `NotAllowedError`/`SecurityError` → tampilkan overlay `#userPlayOverlay` / `#hostPlayOverlay` ("Klik untuk memutar"); gesture berikutnya → `unlockAudioOnGesture()` → `resumeIfPlaying()` → play bersuara. Gagal media (`NotSupportedError`/`AbortError`) → diam, retry di `canplay`. **Target editable** (`input`/`textarea`/`[contenteditable]`/`.chat-input`, via `isEditableTarget`): **jangan** `tryPlay()`/`resumeIfPlaying()` — cegah keyboard mobile tidak terbuka saat tap kolom chat. `resumeIfPlaying()` juga dari `visibilitychange` + `IntersectionObserver`. `loadVideo()` reset `muted` (tidak ada `autoMuted` lagi — tidak pernah ada fallback muted). `#chatInput` `focus` → `hideAllToasts()` + delayed `scrollIntoView({ block: 'nearest' })` (lihat Mobile keyboard). `hideAllToasts()` hanya menyembunyikan `#fsToast`. Chat auto-scroll skip bila `document.activeElement === #chatInput`.
- If app visible but not fullscreen (e.g. session restore): `showFullscreenHint()` shows toast `#fsToast` (auto-hide 4s, click retries). Di `≤900px` `#fsToast` juga di **atas** agar tidak menutup `#chatInput`.
- Posisi judul fullscreen diatur host lewat grup `#btnFsTitleUp` / `#btnFsTitleDown` / `#btnFsTitleReset` (+ readout `#hostFsTitleY`) di `.info-right` (`host.html` saja). Nilai = **persen tinggi frame** (0–60, default `4`, step `2%`) di path `settings/fsTitleY` — **host-only write, semua user read** (aturan `settings/*` yang sudah ada, tidak perlu ubah rules; viewer cuma menerima lewat `listenFsTitlePos()`). Diterapkan ke player sebagai CSS var `--fs-title-y` oleh `applyFsTitleY()` (`js/utils.js`, bersama `clampFsTitleY()`/konstantanya) → `top: var(--fs-title-y, 4%)`, jadi proporsinya sama di HP, laptop, dan 4K. Sanitasi selalu lewat `clampFsTitleY()` — jangan tulis `style.setProperty` langsung, nilai invalid bikin `top` jadi `unset`. Tidak ada write saat page load; path kosong → default.
- **Fullscreen overlay host (counter viewer + pesan chat)** — dua elemen di dalam `.video-frame` (`host.html` saja): `#hostFsViewers.fs-corner` (kanan atas, `top: var(--fs-title-y)` → **sejajar & ikut** tombol ▲▼) berisi `#hostFsViewersText` (`👥 N`, diisi `initViewers()` — total online, sama dengan `#hostViewerCountBar`), dan `#hostFsMsg.fs-msg` (kiri bawah, `bottom: 72px` supaya mengakai `.video-controls` 58px) berisi `#hostFsMsgAvatar` / `#hostFsMsgName` / `#hostFsMsgText` (avatar + nama + isi, maks 2 baris via `-webkit-line-clamp: 2`). Keduanya `display: none` di base dan hanya `display: block` / `display: flex` di `.video-frame:fullscreen` → **tidak muncul** di auto-fullscreen `documentElement` (pola sama `.fs-title`) dan tidak pernah di layout biasa. `#hostFsMsg` punya `hidden` di markup agar tidak ada kilatan kosong. `showFsChatMsg()` dipanggil dari `addChatMessage()` (jadi ikut pesan penonton **dan** host sendiri), pakai `fsMsgTimer` 8 detik: pesan baru mengganti isi + reset timer; `msg.timestamp`OLDER 20 detik **dilewati** — tanpa guard ini `onChildAdded` memutar ulang 200 pesan riwayat saat load dan layar nyesel pesan basi. Nama/isi ditulis lewat `textContent`, avatar lewat `innerHTML` **harus** `escapeHtml`. Judul `.fs-title > span` `max-width` dikecilkan ke `calc(100% - 180px)` (mobile `calc(100% - 110px)`) supaya tidak menabrak counter di kanan.
- Judul film saat fullscreen: elemen `#hostFsTitle` / `#userFsTitle` (`.fs-title`) ada di dalam `.video-frame`, **murni CSS** — `.video-frame:fullscreen .fs-title { display:block }` → hanya tampil saat video frame jadi elemen fullscreen (tombol ⛶), **tidak** saat auto-fullscreen `documentElement`. Teksnya ada di span `#hostFsTitleText` / `#userFsTitleText` (pill gelap + `border-left` merah `#e50914`) dan **wajib** ditulis lewat `setNowTitle()` satu setter di `host.js`/`index.js` yang mengisi `#…NowTitle` **dan** `#…FsTitleText` — jangan tulis `#…FsTitle.textContent` langsung (menghapus span → pill hilang) dan jangan tambah call site `…NowTitle.textContent` yang bypass setter. Fullscreen (iPhone) tidak didukung `Element.requestFullscreen` → fitur otomatis tidak muncul di sana.

## Layout / responsive (`css/style.css` + `css/mobile.css`)

- **Split (opsi A)**: base/desktop rules live in `css/style.css` (no `@media`); **all** breakpoints live in `css/mobile.css` (loaded after via `<link>` on all 3 pages). Add new responsive overrides only in `mobile.css` — do not put `@media` back in `style.css`.
- Breakpoints (in `mobile.css`): `≤1000px` (sidebar 300px, hide `.time`), `≤900px` (stack column, video `aspect-ratio 16/9`, `html/body height: auto` + `padding-bottom: 16px` (spasi keyboard via `initKeyboardPadding()`, bukan statis) + `.app { overflow: visible }` agar scroll saat keyboard terbuka, `#fsToast` top), `≤560px` (phone: header compact, movie-info wrap, form judul/URL full-width + jadwal & Tambah sebaris (judul header `.playlist-title` disembunyikan — redundan dgn tab), touch targets ≥40px, playlist item 2-row), `max-height: 560px` (**viewport pendek**: unlock scroll `html/body/.app` + `.chat` 240px + `#chatInput` 16px — untuk HP/tablet landscape > 900px & jendela pendek, WAJIB supaya kolom chat tidak terkunci `overflow: hidden` saat keyboard naik), `max-height: 480px and (min-width: 561px)` (judul fullscreen landscape), `max-height: 480px and max-width: 900px` (landscape: shorter chat/panels), `@media (hover: none)` (chat delete always visible).
- Judul fullscreen: `.video-frame:fullscreen .fs-title > span` = **22px** di `style.css` (base), **15px** di `≤900px`, **14px** di `≤560px`, **15px** di landscape `max-height: 480px and min-width: 561px` (HP landscape 932px > 900px tidak masuk `≤900px`). `left`/`max-width`/`padding`/`border-left` hanya di-override `≤560px`. Overlay `.fs-corner`/`.fs-msg` mengikuti tier yang sama: counter 15px→13px(`≤900px`)→12px(`≤560px`), pesan 14px→13px(`≤900px`)→12px(`≤560px` dan landscape), avatar 28px→24px.
- Desktop panel heights: `.panel-content.active` and `.viewers.panel-content.active` = **140px** (video is `flex: 1` takes the rest). Mobile overrides use `max-height` (playlist 400px, viewers 220px) — do not raise desktop height without re-checking video size.
- Playlist item grid (base): `28px 1fr auto 32px 32px 32px` (idx | info | badge | sched | play | del). Buttons use `grid-column: -3/-2/-1` so missing badge leaves empty `auto` column. At `≤560px`: explicit 2-row areas (badge on row 2).
- Modal/reschedule + fullscreen toast styles live near top of `style.css` (UTIL / FULLSCREEN HINT / MODAL sections).

## Conventions

- DOM ids are the contract between HTML and JS (`$('id')` at top of each page script). Adding UI: update HTML id, CSS, and the matching page script together.
- `host.html` and `index.html` intentionally diverge (host has controls/playlist/modal; viewer does not). Shared look lives only in `css/style.css` + `css/mobile.css`.
- User-generated strings in HTML: always `escapeHtml` from `js/utils.js` (chat, names, photo URLs, playlist titles/urls).
- `.hidden` class = `display: none !important`. Toggle for overlays/controls/modals.
- Video controls overlay is hidden by default; host toggles with `#btnToggleControls` (bound at module top level, not after login).
- Touch targets on phone (`≤560px`) should stay ≥40px for action buttons; form inputs 36px + `font-size: 16px` to prevent iOS zoom. `#chatInput` di `≤900px` juga `16px` (bukan hanya `≤560px`).
- Only the host writes playlist, `state`, and `settings/*`. Viewers are read-only for those paths.
- Mobile keyboard: `bindChatInputFocus()` dipanggil **di top-level module** (bukan di `initAll`) — focus/wrapper handler siap sebelum login. Wrapper `.chat-input` `pointerdown` → `hideAllToasts()`, **skip kalau target `<button>` (tombol Kirim — jangan fokus, agar keyboard tidak terbuka lagi)**; target selain input → `preventDefault`; selain itu **selalu** `chatInput.focus()` (jangan rely native focus — Android bisa menelan), **tapi `blur()` dulu** kalau `document.activeElement === chatInput && !isKeyboardOpen()` (back gesture Android / tap luar iOS tidak men-blur → `focus` tidak fire lagi, butuh 2 ketukan). **Jangan** pasang `click → focus()` di `chatInput` (redundan + bikin keyboard flicker di Android). `focus` → `hideAllToasts()` + `ensureChatInputVisible()` (scroll hanya kalau `rect.bottom > vv.offsetTop + vv.height - 8` — idempotent, jangan men forcibly scroll tiap tick karena user bisa sedang naik scroll baca pesan lama) + listener `visualViewport.resize` **sekali-pakai** (auto-lepas 700ms tanpa resize) untuk mengikuti settle-nya animasi keyboard — **jangan** pakai `setTimeout` fixed. Viewport meta: `interactive-widget=resizes-content` (Chrome Android resize layout saat keyboard buka). **Breakpoint WAJIB width OR height**: `@media (max-width: 900px), (max-height: 560px)` (CSS di `mobile.css` + `matchMedia` di `initKeyboardPadding`) — HP/tablet landscape (mis. 932×430) dan jendela pendek **tidak** masuk `max-width: 900px`, dan karena `html/body` + `.app` di base itu `height: 100%/100vh; overflow: hidden`, tanpa override ini halaman tidak bisa digulir sama sekali → kolom chat + input terpotong di belakang keyboard dan `scrollIntoView` sia-sia. **Spasi keyboard dinamis**: `initKeyboardPadding()` (duplikat di `host.js`/`index.js`, dipanggil top-level bersama `bindChatInputFocus`) — `kbBaseHeight` (module scope, dipakai juga `isKeyboardOpen()`) = tinggi viewport saat keyboard tertutup; `kb = kbBaseHeight − vv.height`; `kb > 80` → inline `body.style.paddingBottom = kb`, selain itu `16px`; reset `kbBaseHeight` saat `orientationchange` **dan** saat `!mq.matches` (pindah ke layout tinggi); **clear inline saat fullscreen**. `scroll-margin-bottom: 16px` = clearance kecil (ruang scroll dari `initKeyboardPadding`, bukan margin besar). `#chatInput` punya `enterkeyhint="send" autocomplete="off" autocapitalize="sentences"`; `keydown` Enter → `preventDefault()` + `sendChat()`. Tap `.chat` → `hideAllToasts()`. Toast `#fsToast` di `≤900px` juga dipindah ke atas. Viewer: `initChat()` dipanggil **sebelum** `await get(settings/syncMode)` agar listener chat/counter tidak tertahan network. `initChat.done` guard anti double-bind. Kode chat/keyboard di `host.js` & `index.js` harus **identik** (bukan hanya Setara) — ubah di satu file, terusin ke file lain.
- Chat message count `#chatMsgCount`: hitung dari DOM (`chatMessages.querySelectorAll('.message').length`), bukan hanya `chatEls.size` — cegah angka `0` saat pesan tampil. Script di-load dengan `?v=nobar12` (nilai sama di 3 halaman) untuk bust cache module di mobile.

## Gotchas

- `initAll()` runs once per page load (`inited` flag) — do not add Firebase listeners that re-bind on every auth change without a guard.
- Sync/seek hanya dijalankan setelah `timeSynced` (`.info/serverTimeOffset` callback pertama) dan media `readyState >= 2` + duration finite — cegah seek salah di awal load. Viewer: force-seek pertama hanya sekali di `canplay` (flag `initialSeekDone`), reset saat ganti URL/mode/logout.
- HLS: `lowLatencyMode: false`, buffer awal besar (`maxBufferLength: 60`), play pertama ditunda sampai `FRAG_BUFFERED` (timeout 1.5s) agar tidak patah saat mulai. `<video preload="metadata">`. Error fatal: `MEDIA_ERROR` → `recoverMediaError()`, selain itu `startLoad()` (pola sama di `host.js`/`index.js`).
- Live HLS: do not force-seek (duration is Infinity). Seek-sync only when `isFinite(duration)`.
- **Subtitle HLS wajib dimatikan eksplisit.** Default hls.js `subtitleDisplay = true` (lihat `subtitle-track-controller.ts` → `toggleTrackModes()`: `mode = subtitleDisplay ? 'showing' : 'hidden'`), jadi stream yang punya `#EXT-X-MEDIA:TYPE=SUBTITLES ... DEFAULT=YES` (mis. Red Bull TV, 1 track English `GROUP-ID="subs"`) **selalu** auto-tampil. Set `hls.subtitleDisplay = false;` di **instance**, tepat setelah `new Hls({...})` (host.js / index.js) — kalau ditaruh di object config akan diabaikan diam-diam karena `subtitleDisplay` bukan key `HlsConfig`. Durable: `toggleTrackModes()` selalu membaca flag itu tiap kali hls.js memilih track, jadi tetap mati walau live manifest di-reload / quality di-switch. `suppressSubtitles(video)` (dipanggil sekali dari `initPlayer()` kedua file, guard `suppressSubtitles.done === video`) adalah jaring pengaman untuk **HLS native** (Safari/iOS, `Hls.isSupported()` false): memaksa `mode 'showing' → 'hidden'` + listener `textTracks` `change`. Syarat `=== 'showing'` membuat rantai event konvergen (terukur 2 event per penyalaan ulang, konstan, bukan loop). Mode `'hidden'` **tetap** mengisi `activeCues` → hook untuk subtitle terjemahan di masa depan tanpa mengubah kode ini. `TYPE=CLOSED-CAPTIONS` (CEA-608/708) tidak dirender Chrome/Edge lewat `<video>` dan tidak bisa dimatikan dari JS (itu setelan OS/browser).
- **Foto profil tidak boleh pernah tertimpa kosong.** `photo` pada `users/{uid}` hanya ditulis kalau sesi itu benar-benar punya `user.photoURL` (`...(user.photoURL ? { photo: user.photoURL } : {})`) — kalau tidak, satu sesi dengan `photoURL` null akan menghapus foto yang sudah tervalidasi dan tidak kembali sampai ada sesi non-kosong. Pola ini dipakai di 4 call site: `login.js` `routeAfterLogin()` (cabang host **dan** viewer), `host.js` `registerHost()`, `index.js` `registerViewer()`. Host juga **wajib** pakai `update`, bukan `set`: `set` menghapus SELURUH node tiap `host.html` dibuka. Ketiganya menambah `email: null` agar key `email` legacy ikut terhapus (`users` dibaca semua user terautentikasi). Trade-off yang diterima sadar: kalau user menghapus foto Google-nya, foto lama tetap tampil. Perbaikan ini **tidak** memulihkan foto yang sudah kosong di DB — user terdampak cukup login sekali lagi untuk menuliskannya ulang.
- Presence pakai `onDisconnect` saja (tidak ada `beforeunload` write — tidak andal saat unload). User tanpa Google photo: `users/{uid}.photo` kosong → render pakai `userAvatarHtml()` (avatar huruf) dan `#hostPhoto` di-`display:none`, jangan `src=""` (gambar broken). `initViewers()` iterasi `Object.entries` dan menentukan slot host dari **`uid === HOST_UID`**, bukan `role` dari DB — record lama/salah dengan `role: 'host'` dulu membuat user lain hilang dari daftar karena `hostHtml` menimpa. Node `null`/rusak di-skip (`if (!u || !u.online) return`) supaya satu record rusak tidak mematikan seluruh panel. **Avatar daftar penonton WAJIB pakai struktur yang sama dengan avatar chat**: huruf selalu ada di dalam `.message-avatar`, foto menimpanya (`position:absolute`) + `onerror="this.remove()`. `utils.js` → `avatarHtml(name, photo)` adalah satu-satunya pembentuk markup avatar; `userAvatarHtml(user)` menempelkan `<span class="name">` di atasnya dan `addChatMessage()` (`host.js`/`index.js`) memakai `avatarHtml(msg.name, msg.photo)` — jangan tulis ulang markup avatar inline di file mana pun. `guardAvatarImages(root)` (utils.js) WAJIB dipanggil setelah tiap `innerHTML`/`appendChild` yang memuat avatar: `renderViewers()` → 2 section, `addChatMessage()` → elemen pesan. Atribut `onerror` inline saja tidak cukup: kalau URL-nya **sudah gagal-ter-cache**, event `error` bisa menyala sebelum handler terpasang sehingga tidak pernah jalan dan huruf di baliknya tidak pernah terekspos (kotak kosong menutupi huruf). Penanda anti-dobel-binding memakai properti JS `img.avatarGuard` — **jangan** pakai `dataset`, browser lama tidak punya `HTMLElement.dataset` dan guard lalu ter-skip. Jangan emit `<img>` polos di `userAvatarHtml()` — URL foto Google yang gagal load jadi ikon gambar rusak di panel penonton (chat sudah aman karena `addChatMessage` pakai `onerror`). Nama panjang di `.viewer-item`/`.viewer-item-host` wajib `min-width: 0` + ellipsis + `max-width: 100%`, kalau tidak avatar 26px ikut ter-shrink ke arah 0 (`.message img` sudah ada `flex-shrink: 0`, `.viewer-item img` tidak). Presence berbasis `onDisconnect`, **tanpa grace period — sengaja**: begitu `online: false` (tombol Keluar, tab ditutup, koneksi putus) user langsung hilang dari menu penonton. `renderViewers(users)` menerima data sebagai parameter (dipanggil dari `onValue(users)`, **tanpa `setInterval`** — tanpa grace period daftar hanya berubah saat event `users`); filter cukup `if (!u || !u.online) return;`. `viewersSig` + signature `count|hostHtml|userHtml` tetap dipertahankan: `lastSeen`/`role` tidak ikut dirender, jadi tanpa guard tiap reconnect hanya mengubah `lastSeen` dan seluruh `innerHTML` daftar dibangun ulang. `lastSeen` **tetap** diisi `serverTimestamp()` saat disconnect karena rules `users/{uid}.validate` mewajibkan `name`+`online`+`lastSeen` ada (sekarang hanya jejak audit). Flag `leaving` (di-set `true` di handler `#btnLogout`) ditambahkan ke guard handler reconnect `.info/connected` → `snap.val() && currentUser && !leaving`, supaya `online: true` tidak ditulis ulang di antara `update({online:false})` dan `onAuthStateChanged(null)` (nama akan muncul sesaat lalu hilang = flicker). Konsekuensi yang disepakati: penonton yang tabnya ter-suspend ~60 detik ikut hilang-tampil.
- After a playlist video ends, call `playDefault(true)` (force); non-force no-ops if `state.currentUrl` still set.
- Google sign-in requires this origin in Firebase Auth authorized domains.
- Async mode: YouTube iframe seek is only applied via `&start=` on load (no continuous re-sync). Gap after a VOD item ends is tracked with `asyncGapId` so the 1s `tickAsync()` does not reload the finished item before the next schedule.
- Reschedule of an *active* item only changes `scheduledTime`; leave `state` alone (playback continues by design).
- Clearing schedule uses `scheduledTime: null` in RTDB `update` (removes key), not empty string.
- Fullscreen toast and modal handlers are bound once in `initPlaylist()` / via `showFullscreenHint` self-init — do not re-bind on every `renderPlaylist()`.
- Known limitation: YouTube di mode sync tidak pernah di-seek (iframe tanpa akses `currentTime`; drift bebas). Satu akun Google dibuka di host.html + index.html = 1 record `users/{uid}` (role/online bisa saling menimpa antar tab).
- Deploy rules: `database.rules.json` harus di-deploy ke RTDB project (`firebase deploy --only database` atau tempel di Console → Rules) sebelum aturan host-only aktif.
